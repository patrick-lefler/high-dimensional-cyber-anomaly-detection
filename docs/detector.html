Cyber Anomaly Detection & Dependency Risk: synthetic telemetry, attack scenarios, and a base-R autoencoder

Unit of observation

One row = one host × one 5-minute window, with that window’s authentication activity for the host’s users joined in. Each simulated host runs for 14 days (4,032 windows) starting on a Monday. Hosts are split, not windows, so the model is always scored on hosts it has never seen:

Set Hosts Windows Use
Training 4 16,128 Fit preprocessing and the autoencoder
Validation (held-out) 4 16,128 Early stopping and the EVT threshold fit
Test, normal 2 8,064 Measure false alarms
Test, attacks 4 (attack pool) 3,120 Measure detection

All data on this site are simulated. Every parameter is in params.yaml and labelled as an assumption.

How to read the table. Each row is one slice of the simulated data. A host is one simulated machine, and a window is five minutes of its activity, so one host over 14 days contributes 4,032 windows. The last column says what each slice is used for. Training data teaches the model what normal looks like. The other slices come from different hosts and are used only to set thresholds and to measure performance.

What the table tells you. The model is always judged on machines it has never seen, which is closer to a real deployment than reusing windows from the same machines. The test set holds 8,064 normal windows and 3,120 attack windows, so attacks make up about 28% of it, far more than on any real network. That proportion flatters some measures, which the Evaluation page corrects for.

Telemetry generator

The original version of this study drew all 16 features independently. With independent, unit-variance inputs, a 4-unit bottleneck can at best keep 4 of 16 dimensions, so the lowest achievable reconstruction error was \(12/16 = 0.75\). That was exactly where the old training curve flattened. The plateau did not show the model learning business patterns. It showed the model hitting the floor for data with no structure to learn.

The generator now has structure. Each feature is driven by shared latent factors through a Gaussian copula:

  • Business activity follows a daily cycle peaking at 13:00, is lower at weekends (30% of the weekday peak), and has AR(1) persistence (\(\phi = 0.5\)).
  • Host workload, plus shared network-volume, authentication-volume and process-activity factors, each AR(1) with \(\phi = 0.5\).
  • Host role, a constant per host, so hosts differ from one another, as real fleets do.

For each window the latent factors plus independent noise give correlated standard-normal scores. pnorm() turns these into uniforms, and the quantile function of each target distribution (qpois, qlnorm, qbeta, …) maps them onto realistic marginals. Three features were added to support a real lateral-movement scenario: new destination hosts, SMB/RDP/WinRM connections and new service creations. That makes \(d = 19\).

Attack scenarios

Each attack is injected into real normal windows from separate attack-pool hosts, at three intensity tiers with 150 windows per cell. The high tier reproduces the original study’s magnitudes. The low tier is the stealthy case.

Preprocessing

A recipes pipeline applies a Yeo-Johnson transform and then standardizes each feature to zero mean and unit variance. Both steps are estimated on the training hosts only and applied unchanged to validation and test windows, so no information leaks from evaluation data.

Shallow autoencoder

Architecture. Let \(X \in \mathbb{R}^{N \times d}\) be a batch of \(N\) windows across \(d = 19\) features. The encoder maps to a \(k = 4\)-unit bottleneck with a \(\tanh\) activation, and a linear decoder maps back:

\[Z = \tanh\left(X W_e + \mathbf{1}_N \mathbf{b}_e^\top\right), \qquad \hat{X} = Z W_d + \mathbf{1}_N \mathbf{b}_d^\top,\]

with \(W_e \in \mathbb{R}^{d \times k}\), \(\mathbf{b}_e \in \mathbb{R}^k\), \(W_d \in \mathbb{R}^{k \times d}\), \(\mathbf{b}_d \in \mathbb{R}^d\). One hidden layer with a linear decoder is a shallow autoencoder, close to principal component analysis. The sensitivity table below confirms this.

Loss. Training minimizes the batch mean squared error, and each window is scored by its own mean squared error over features:

\[\mathcal{L}(X, \hat{X}) = \frac{1}{N d}\,\lVert X - \hat{X} \rVert_F^2, \qquad \ell(\mathbf{x}) = \frac{1}{d}\,\lVert \mathbf{x} - \hat{\mathbf{x}} \rVert^2 .\]

Gradients. By matrix calculus,

\[\frac{\partial \mathcal{L}}{\partial \hat{X}} = \frac{2}{N d}(\hat{X} - X), \quad \frac{\partial \mathcal{L}}{\partial W_d} = Z^\top \frac{\partial \mathcal{L}}{\partial \hat{X}}, \quad \frac{\partial \mathcal{L}}{\partial \mathbf{b}_d} = \mathbf{1}_N^\top \frac{\partial \mathcal{L}}{\partial \hat{X}},\]

\[\Delta_Z = \left(\frac{\partial \mathcal{L}}{\partial \hat{X}} W_d^\top\right) \odot (1 - Z^2), \quad \frac{\partial \mathcal{L}}{\partial W_e} = X^\top \Delta_Z, \quad \frac{\partial \mathcal{L}}{\partial \mathbf{b}_e} = \mathbf{1}_N^\top \Delta_Z .\]

Parameters are updated with Adam (bias-corrected first and second moments, learning rate 0.005, batch size 256) from Xavier-initialized weights. Training stops early when validation loss has not improved for 5 epochs, and the best weights are kept. The implementation (R/ae.R) handles any stack of \(\tanh\) layers, which the sensitivity check uses.

How to read the table. The autoencoder learns by following gradients: formulas that say how to adjust each weight to reduce error. We derived these by hand. Each row compares the hand-derived gradient for one block of weights with a brute-force estimate obtained by nudging every weight slightly and measuring how the error changes. The relative error column shows how far apart the two answers are, as a share of their size.

What the table tells you. The largest disagreement is 3.4e-10, far below the one-in-a-million pass mark, for both the shallow model and the deeper variant. The hand-derived mathematics and the code that implements it agree, so the model is learning what we think it is learning. The unit tests repeat this check automatically every time the project runs, so a later code change cannot silently break the training.

## Attack scenarios

Each attack is injected into real normal windows from separate attack-pool hosts, at three intensity tiers with `r sim$n_attacks_per_cell` windows per cell. The high tier reproduces the original study's magnitudes. The low tier is the stealthy case.

## Preprocessing

A `recipes` pipeline applies a Yeo-Johnson transform and then standardizes each feature to zero mean and unit variance. Both steps are estimated on the training hosts only and applied unchanged to validation and test windows, so no information leaks from evaluation data.

## Shallow autoencoder

**Architecture.** Let $X \in \mathbb{R}^{N \times d}$ be a batch of $N$ windows across $d = `r d_features`$ features. The encoder maps to a $k = `r k`$-unit bottleneck with a $\tanh$ activation, and a linear decoder maps back:

$$Z = \tanh\left(X W_e + \mathbf{1}_N \mathbf{b}_e^\top\right), \qquad \hat{X} = Z W_d + \mathbf{1}_N \mathbf{b}_d^\top,$$

with $W_e \in \mathbb{R}^{d \times k}$, $\mathbf{b}_e \in \mathbb{R}^k$, $W_d \in \mathbb{R}^{k \times d}$, $\mathbf{b}_d \in \mathbb{R}^d$. One hidden layer with a linear decoder is a **shallow** autoencoder, close to principal component analysis. The sensitivity table below confirms this.

**Loss.** Training minimizes the batch mean squared error, and each window is scored by its own mean squared error over features:

$$\mathcal{L}(X, \hat{X}) = \frac{1}{N d}\,\lVert X - \hat{X} \rVert_F^2, \qquad \ell(\mathbf{x}) = \frac{1}{d}\,\lVert \mathbf{x} - \hat{\mathbf{x}} \rVert^2 .$$

**Gradients.** By matrix calculus,

$$\frac{\partial \mathcal{L}}{\partial \hat{X}} = \frac{2}{N d}(\hat{X} - X), \quad
\frac{\partial \mathcal{L}}{\partial W_d} = Z^\top \frac{\partial \mathcal{L}}{\partial \hat{X}}, \quad
\frac{\partial \mathcal{L}}{\partial \mathbf{b}_d} = \mathbf{1}_N^\top \frac{\partial \mathcal{L}}{\partial \hat{X}},$$

$$\Delta_Z = \left(\frac{\partial \mathcal{L}}{\partial \hat{X}} W_d^\top\right) \odot (1 - Z^2), \quad
\frac{\partial \mathcal{L}}{\partial W_e} = X^\top \Delta_Z, \quad
\frac{\partial \mathcal{L}}{\partial \mathbf{b}_e} = \mathbf{1}_N^\top \Delta_Z .$$

Parameters are updated with Adam (bias-corrected first and second moments, learning rate `r cfg$autoencoder$lr`, batch size `r cfg$autoencoder$batch_size`) from Xavier-initialized weights. Training stops early when validation loss has not improved for `r cfg$autoencoder$patience` epochs, and the best weights are kept. The implementation (`R/ae.R`) handles any stack of $\tanh$ layers, which the sensitivity check uses.
